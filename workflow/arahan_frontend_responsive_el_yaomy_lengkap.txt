ARAHAN LENGKAP FRONTEND SISTEM TERPADU EL YAOMY
Web Desktop, Web HP, Android WebView, React HTML, Mobile Friendly, Aman, Fleksibel, Mudah Digunakan

Versi dokumen: 1.0
Target teknologi:
- Frontend: React + HTML + CSS responsif
- Backend: Python API
- Database: PostgreSQL
- Platform akses: desktop browser, mobile browser, Android WebView
- Prioritas: mudah digunakan semua role, aman, ringan, konsisten, siap dikembangkan

=====================================================================
1. TUJUAN UTAMA FRONTEND
=====================================================================

Frontend harus menjadi pintu utama semua pengguna untuk memakai sistem keuangan, sekolah, kantin, RFID, tabungan, aset, laporan, dan approval.

Tujuan utama:
1. Satu tampilan yang konsisten untuk semua modul.
2. Bisa dipakai di laptop/PC, tablet, HP browser, dan Android WebView.
3. Setiap role hanya melihat menu dan data yang memang boleh diakses.
4. Semua transaksi penting dibuat mudah tetapi tetap aman.
5. UI tidak membingungkan user non-teknis.
6. Desain elegan, minimalis, cepat, dan rapi.
7. Semua fitur backend bisa diakses dari UI sesuai role.
8. Frontend tidak boleh menyimpan data sensitif secara sembarangan.
9. Semua aksi penting punya konfirmasi, validasi, dan feedback jelas.
10. Sistem tetap nyaman dipakai kasir, bendahara, guru, orang tua, siswa, kepala sekolah, admin, auditor, petugas kantin, dan petugas aset.

Prinsip paling penting:
- User tidak perlu paham struktur database.
- User tidak perlu hafal menu rumit.
- User cukup mengikuti alur kerja yang jelas.
- Semua tombol penting harus mudah ditemukan.
- Semua error harus dijelaskan dengan bahasa manusia.
- Semua transaksi uang harus transparan dan bisa diaudit.

3. PRINSIP DESAIN UI/UX
=====================================================================

3.1 Minimalis
- Gunakan ruang kosong yang cukup.
- Hindari terlalu banyak warna.
- Hindari terlalu banyak tombol dalam satu layar.
- Tampilkan fitur utama sesuai konteks.
- Fitur lanjutan masuk ke menu More atau Lainnya.

3.2 Konsisten
- Posisi tombol Simpan selalu di kanan bawah atau area akhir form.
- Tombol batal/kembali selalu di kiri atau sekunder.
- Warna status sama di semua modul.
- Format tanggal, uang, dan nomor transaksi konsisten.

3.3 Mobile-first
- Semua halaman harus tetap bisa dipakai di layar 360px.
- Tombol minimal tinggi 44px agar mudah disentuh.
- Input tidak terlalu kecil.
- Tabel desktop harus berubah menjadi card/list di HP.
- Menu sidebar desktop berubah menjadi bottom navigation atau drawer di HP.

3.4 Role-first
- Jangan tampilkan menu yang tidak boleh dipakai user.
- Jangan hanya disable tombol; lebih baik sembunyikan fitur yang tidak relevan.
- Jika fitur muncul tetapi butuh izin tambahan, tampilkan pesan jelas.

3.5 Error yang manusiawi
Contoh buruk:
- Error 403.
- Validation failed.
- Internal server error.

Contoh baik:
- Anda tidak punya izin untuk membuka data siswa ini.
- Nominal top-up melebihi limit harian guru.
- Saldo siswa tidak cukup untuk transaksi ini.
- Koneksi terputus. Transaksi belum diproses. Silakan coba lagi.

3.6 Feedback langsung
Setiap aksi harus memberi respons:
- Loading saat proses.
- Sukses saat berhasil.
- Error saat gagal.
- Peringatan saat data berisiko.
- Konfirmasi sebelum aksi besar.

3.7 Tidak membingungkan pengguna
- Jangan memakai istilah teknis untuk orang tua/siswa.
- Gunakan istilah sederhana: Tagihan, Bayar, Saldo, Riwayat, Kartu Hilang.
- Istilah teknis seperti jurnal, COA, rekonsiliasi hanya muncul untuk bendahara/admin.

7.2 MFA/OTP
Untuk role sensitif:
- Super admin.
- Bendahara.
- Admin keuangan.
- User yang melakukan refund/void/adjustment.

Flow:
1. User login.
2. Backend meminta OTP/MFA jika dibutuhkan.
3. Frontend menampilkan halaman verifikasi.
4. Setelah berhasil, user masuk dashboard.

Pseudocode:

FUNCTION login(form):
    response = api.post('/auth/login', form)

    IF response.status == 'mfa_required':
        navigate('/verify-mfa', { challenge_id })
    ELSE:
        setSession(response.user)
        navigate('/dashboard')

7.3 Session timeout
UI harus menangani:
- Session habis.
- Token expired.
- User dikunci.
- Role berubah.

Jika session habis:
- Tampilkan dialog: Sesi Anda berakhir, silakan masuk kembali.
- Jangan hilangkan data form langsung jika bisa disimpan sementara secara aman.

7.4 Re-authentication
Untuk aksi sensitif:
- Top-up besar.
- Refund.
- Void transaksi.
- Blokir/unblock kartu.
- Ubah role user.
- Hapus data master.
- Posting/unposting jurnal.
- Reopen periode.

UI:
- Tampilkan dialog input password/PIN/OTP.
- Jelaskan kenapa diminta.

Pseudocode:

FUNCTION sensitiveAction(action):
    IF action.requires_reauth:
        result = showReAuthDialog()
        IF result.failed:
            STOP

    executeAction()

9. DATA FETCHING, CACHE, DAN ERROR HANDLING
=====================================================================

9.1 API client
Semua request harus lewat satu apiClient.

Tugas apiClient:
- Menambah header CSRF jika diperlukan.
- Mengirim cookie otomatis.
- Menangani 401.
- Menangani 403.
- Menangani 422 validation error.
- Menangani 500 tanpa membocorkan detail.
- Menambahkan request_id/idempotency_key untuk transaksi tertentu.

Pseudocode:

FUNCTION apiRequest(method, url, body, options):
    request_id = generateUUID()

    headers = {
        'Content-Type': 'application/json',
        'X-Request-Id': request_id
    }

    IF options.idempotent:
        headers['Idempotency-Key'] = options.idempotencyKey OR generateUUID()

    response = fetch(url, {
        method,
        credentials: 'include',
        headers,
        body: JSON.stringify(body)
    })

    IF response.status == 401:
        showSessionExpiredDialog()
        THROW AuthError

    IF response.status == 403:
        THROW ForbiddenError

    IF response.status == 422:
        THROW ValidationError(response.errors)

    IF response.status >= 500:
        THROW ServerError('Server sedang bermasalah. Silakan coba lagi.')

    RETURN response.json()

9.2 Cache
Gunakan cache untuk data baca:
- Dashboard.

Jangan cache sembarangan untuk:

Setelah transaksi berhasil:

9.3 Loading state

10. FORM DAN VALIDASI
=====================================================================

10.1 Aturan umum form
- Label selalu terlihat, jangan hanya placeholder.
- Input uang otomatis format Rupiah.
- Tanggal pakai date picker tetapi tetap bisa diketik.
- Required field diberi tanda jelas.
- Error muncul dekat field.
- Tombol Simpan disabled saat proses.
- Tekan Enter tidak boleh memicu transaksi uang tanpa konfirmasi.

10.2 Money input
Aturan:
- Simpan sebagai integer rupiah.
- Tampilkan dengan format Rp.
- Tidak boleh negatif kecuali modul koreksi tertentu.
- Maksimal mengikuti limit role.

Pseudocode:

FUNCTION MoneyInput(value):
    displayValue = formatRupiah(value)

    ON change(text):
        numeric = parseRupiah(text)
        IF numeric < 0:
            showError('Nominal tidak boleh negatif')
        ELSE:
            setValue(numeric)

10.3 Validasi frontend vs backend
Frontend:
- Untuk pengalaman user cepat.
- Mencegah input salah umum.

Backend:
- Sumber validasi final.
- Tidak boleh percaya frontend.

10.4 Form transaksi sensitif
Untuk pembayaran, top-up, refund, void:
- Tampilkan ringkasan sebelum submit.

- Normalisasi UID.
- Mengirim scan ke backend.

Pseudocode React:

FUNCTION useRfidScanner(context):
    buffer = ''
    lastScan = null

    ON keydown(event):
        IF context not active:
            RETURN

        IF event.key == 'Enter':
            uid = normalize(buffer)
            buffer = ''

            IF uid is valid AND not duplicate(uid):
                sendScan(uid)
        ELSE:
            buffer += event.key

    FUNCTION sendScan(uid):
        api.post('/rfid/scan', {
            raw_uid: uid,
            context,
            terminal_id
        })

FUNCTION isDuplicate(uid):
    now = currentTime()
    IF lastScan.uid == uid AND now - lastScan.time < 2000:
        RETURN true
    lastScan = { uid, time: now }
    RETURN false

=====================================================================
25. SECURITY FRONTEND
=====================================================================

25.1 Prinsip utama
Frontend tidak pernah dipercaya penuh.
Semua validasi penting tetap di backend.
Tetapi frontend harus mencegah kesalahan dan serangan umum.

25.2 Token dan session
Rekomendasi:
- Gunakan cookie HttpOnly + Secure + SameSite untuk session.
- Jangan simpan access token sensitif di localStorage.
- CSRF protection jika menggunakan cookie.
- Logout harus memanggil backend untuk invalidasi session.

25.3 XSS prevention
Aturan:
- Jangan render HTML mentah dari database.
- Hindari dangerouslySetInnerHTML.
- Jika harus render HTML, sanitize terlebih dahulu.
- Escape output user.
- Validasi upload file.

25.4 CSRF
Jika pakai cookie session:
- Backend menyediakan CSRF token.
- Frontend mengirim X-CSRF-Token untuk POST/PUT/PATCH/DELETE.
- SameSite cookie tetap aktif.

25.5 Clickjacking
Frontend tidak mengatur sendiri, tetapi harus cocok dengan header backend:
- frame-ancestors 'none'
Khusus WebView official app harus dipikirkan oleh backend/domain policy.

25.6 Content Security Policy
Frontend harus dibuat supaya bisa jalan dengan CSP ketat:
- Hindari inline script.
- Hindari eval.
- Load asset dari domain sendiri.
- Batasi connect-src ke API resmi.

25.7 Input validation
Validasi sisi frontend:
- Email/phone format.
- Nominal uang.
- Tanggal.
- File upload size/type.
- Required field.

Tetapi jangan menganggap validasi frontend cukup.

25.8 File upload security UI
Saat upload:
- Tampilkan file name, size, type.
- Batasi PDF/JPG/PNG sesuai kebutuhan.
- Maksimal ukuran file.
- Jangan preview file HTML/SVG mentah.

25.9 Frontend logging
Jangan log:
- Password.
- PIN.
- OTP.
- Token.
- Raw UID RFID jika tidak perlu.
- Data pribadi sensitif.

Boleh log:
- Error code.
- Request ID.
- Page name.
- Module.
- Waktu.

25.10 Anti double submit
Semua tombol transaksi harus:
- Disabled saat loading.
- Memakai idempotency key.
- Tidak bisa diklik dua kali.

Pseudocode:

FUNCTION SubmitButton(onSubmit):
    loading = false

    ON click:
        IF loading:
            RETURN
        loading = true
        TRY:
            await onSubmit()
        FINALLY:
            loading = false

25.11 Data masking
Untuk data sensitif:
- Nomor HP tampil sebagian untuk role tertentu.
- Email bisa dimasking.
- Data pribadi siswa hanya untuk role berwenang.

25.12 Screen lock untuk kasir
Jika kasir idle:

34.5 Transaction submit

FUNCTION submitTransaction(payload, endpoint):
    idempotencyKey = generateUUID()

    showConfirm(payload.summary)

    IF user cancels:
        RETURN

    setLoading(true)

    TRY:
        response = api.post(endpoint, payload, {
            idempotent: true,
            idempotencyKey
        })
        showSuccess(response.message)
        refreshRelatedData()
    CATCH ValidationError as e:
        showFormErrors(e)
    CATCH NetworkError:
        showUncertainStateWarning()
    FINALLY:
        setLoading(false)

FUNCTION StatusBadge(status):
    map = {
        'paid': { label: 'Lunas', color: 'success' },
        'unpaid': { label: 'Belum Lunas', color: 'danger' },
        'partial': { label: 'Sebagian', color: 'info' },

        'blocked': { label: 'Diblokir', color: 'danger' },
        'active': { label: 'Aktif', color: 'success' }
    }

    config = map[status] OR { label: status, color: 'muted' }
    RETURN Badge(config.label, config.color)
