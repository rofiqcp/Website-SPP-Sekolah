Masukan paling penting: **desain awal sudah bagus, tapi untuk implementasi nyata harus disederhanakan dan diperkuat di area RFID, top-up, kasir kantin, dan server lokal.** Jangan langsung membuat semua modul besar sekaligus. Untuk Yayasan El Yaomy, saya sarankan sistem dibuat bertahap tetapi fondasinya tetap benar.

Inti review saya:

1. **Saldo tidak boleh disimpan di kartu RFID.**
2. **Kartu RFID hanya sebagai identitas/token.**
3. **Saldo asli tetap di server PostgreSQL.**
4. **PC client kantin hanya alat transaksi, bukan sumber data utama.**
5. **Semua top-up, pembayaran, refund, void, dan koreksi harus lewat server utama.**
6. **Admin/guru boleh top-up hanya kalau punya role dan limit yang jelas.**
7. **Kartu hilang harus bisa langsung diblokir.**
8. **RFID UID saja tidak cukup aman untuk nominal besar.**

Untuk aplikasi sekolah, pendekatan ini lebih mudah diimplementasikan dan jauh lebih aman.

# 2. Catatan Penting Tentang RFID

## Jangan gunakan UID kartu sebagai satu-satunya keamanan

Banyak kartu RFID murah hanya mengirim UID. UID bisa dibaca dan pada beberapa jenis kartu bisa dikloning. Jadi kalau sistem hanya begini:

```text
Scan UID -> ambil saldo -> bayar
```

itu **kurang aman**.

Lebih aman:

```text
Scan kartu -> baca token kartu -> kirim ke server -> server validasi kartu aktif -> server cek saldo -> server proses transaksi
```

Untuk aplikasi yang butuh keamanan, NXP sendiri menyarankan keluarga MIFARE DESFire atau MIFARE Plus untuk security-relevant applications, bukan MIFARE Classic. ([NXP][1]) MIFARE DESFire EV3 juga memang diposisikan sebagai secure contactless IC dan mendukung mekanisme kriptografi seperti AES. ([NXP][2])

## Rekomendasi jenis kartu

### Opsi murah / MVP

```text
Kartu RFID 13.56 MHz UID-only
Reader USB umum
Saldo tetap di server
Limit transaksi rendah
Wajib online ke server
Kartu bisa diblokir
```

Kelebihan:

```text
- Murah
- Mudah dibuat
- Cepat implementasi
```

Kekurangan:

```text
- UID bisa berisiko dikloning
- Cocok hanya untuk nominal kecil
- Harus diperkuat dengan limit, audit, dan blokir cepat
```

### Opsi lebih aman

```text
MIFARE DESFire EV2 / EV3
Reader yang mendukung DESFire
Key per sekolah
Mutual authentication
Token terenkripsi
Saldo tetap di server
```

Kelebihan:

```text
- Lebih sulit dikloning
- Cocok untuk sistem kantin dan dompet siswa
- Bisa pakai diversified key per kartu
```

Kekurangan:

```text
- Biaya kartu dan reader lebih mahal
- Implementasi lebih teknis
```

## Rekomendasi saya

Untuk El Yaomy:

```text
Tahap awal:
RFID UID-only boleh, tetapi hanya sebagai identitas, bukan penyimpan saldo.

Tahap aman:
Gunakan MIFARE DESFire EV3 untuk kartu resmi siswa.
```

# 3. Prinsip Paling Penting: Jangan Simpan Saldo di Kartu

Desain yang salah:

```text
Kartu menyimpan saldo Rp50.000

Server hanya mencatat belakangan
```

Masalah:


```text

Saldo ada di server PostgreSQL
Semua transaksi diproses server

```

Alur aman:

```text
Siswa tap kartu
Reader membaca card_uid/card_token
PC client kirim ke backend
Backend cek kartu aktif
Backend cek siswa
Backend cek wallet
Backend cek limit
Backend potong saldo
Backend simpan ledger
Backend kirim hasil ke client
Client cetak struk
```

# 8. Alur Top-up RFID

```text
Admin/guru login di PC client
Admin/guru scan kartu siswa
Sistem tampilkan nama siswa dan saldo
Admin/guru input nominal top-up
Sistem cek role dan limit
Sistem minta konfirmasi
Jika perlu, minta PIN/password ulang
Sistem simpan transaksi top-up
Saldo wallet bertambah
Ledger tercatat
Jika tunai, kas bertambah
Struk dicetak
Orang tua mendapat notifikasi
```

Pseudo-code:

```text
FUNCTION topup_by_rfid(actor, device_id, raw_card_uid, amount, payment_method):
    authorize_device(device_id, module = "topup")
    authorize(actor, "wallet.topup")

    card_uid_hash = hmac_sha256(SERVER_SECRET, raw_card_uid)

    card = find_card_by_uid_hash(card_uid_hash)

    IF card not found:
        REJECT "Kartu tidak dikenal"

    IF card.status != "active":
        REJECT "Kartu tidak aktif"

    student = get_student(card.student_id)
    wallet = get_wallet(student.id)

    IF actor.role == "teacher":
        IF student.class_id not in actor.allowed_classes:
            REJECT "Guru hanya boleh top-up siswa kelasnya"
        IF amount > TEACHER_SINGLE_TOPUP_LIMIT:
            REJECT "Nominal melebihi limit guru"

    IF amount <= 0:
        REJECT "Nominal tidak valid"

    IF is_sensitive_amount(actor, amount):
        require_reauthentication(actor)

    BEGIN_TRANSACTION
        locked_wallet = lock_wallet(wallet.id)

        tx = create_wallet_transaction(
            wallet_id = wallet.id,
            type = "topup",
            amount = amount,
            device_id = device_id,
            created_by = actor.id,
            status = "success"
        )

        insert_wallet_ledger(
            wallet_id = wallet.id,
            direction = "credit",
            amount = amount,
            balance_before = locked_wallet.cached_balance,
            balance_after = locked_wallet.cached_balance + amount,
            source_module = "topup",
            source_id = tx.id
        )

        update_wallet_balance(wallet.id, locked_wallet.cached_balance + amount)

        IF payment_method == "cash":
            create_cash_movement(
                type = "in",
                amount = amount,
                source = tx.id
            )

        create_journal_for_wallet_topup(tx)

        create_audit_log(actor, "wallet.topup.rfid", tx.id)
    COMMIT

    send_notification_to_guardian(student.id, tx)

    RETURN success
```

OWASP menyarankan re-authentication untuk aktivitas kritis seperti perubahan detail sensitif atau operasi berisiko tinggi. Top-up besar, refund, void, dan adjustment saldo termasuk aksi yang layak diberi re-authentication. ([OWASP Cheat Sheet Series][3])

# 9. Alur Pembayaran Kantin RFID

```text
Petugas kantin login
Siswa tap kartu

Petugas pilih item makanan/minuman
Sistem hitung total
Sistem cek saldo

Sistem proses pembayaran
Saldo berkurang
Stok berkurang
Ledger tercatat
Order kantin tercatat
Struk dicetak opsional
Notifikasi ke orang tua opsional
```

Pseudo-code:

```text
FUNCTION canteen_pay_by_rfid(cashier, device_id, raw_card_uid, cart_items):
    authorize_device(device_id, module = "canteen")
    authorize(cashier, "canteen.checkout")

    IF not active_cashier_session(cashier.id):
        REJECT "Kasir belum buka shift"

    card_uid_hash = hmac_sha256(SERVER_SECRET, raw_card_uid)
    card = find_card_by_uid_hash(card_uid_hash)

    IF card is null:
        REJECT "Kartu tidak terdaftar"

    IF card.status != "active":
        REJECT "Kartu diblokir/tidak aktif"

    student = get_student(card.student_id)
    wallet = get_wallet(student.id)

    total = calculate_cart_total(cart_items)

    IF total <= 0:
        REJECT "Keranjang tidak valid"

    IF total > wallet.cached_balance:
        REJECT "Saldo tidak cukup"

    IF total > wallet.single_transaction_limit:
        REJECT "Melebihi limit per transaksi"

    today_spent = get_today_canteen_spending(student.id)

    IF today_spent + total > wallet.daily_spending_limit:
        REJECT "Melebihi limit harian"

    BEGIN_TRANSACTION
        locked_wallet = lock_wallet(wallet.id)

        IF locked_wallet.cached_balance < total:
            REJECT "Saldo berubah, tidak cukup"

        order = create_canteen_order(
            student_id = student.id,
            cashier_id = cashier.id,
            device_id = device_id,
            total = total,
            status = "paid"
        )

        FOR item IN cart_items:
            product = lock_product(item.product_id)

            IF product.stock_tracking_enabled:
                IF product.stock < item.qty:
                    REJECT "Stok tidak cukup"
                decrease_stock(product.id, item.qty)

            create_canteen_order_item(order.id, item)

        tx = create_wallet_transaction(
            wallet_id = wallet.id,
            type = "canteen_payment",
            amount = total,
            source_id = order.id,
            status = "success"
        )

        insert_wallet_ledger(
            wallet_id = wallet.id,
            direction = "debit",
            amount = total,
            balance_before = locked_wallet.cached_balance,
            balance_after = locked_wallet.cached_balance - total,
            source_module = "canteen",
            source_id = order.id
        )

        update_wallet_balance(wallet.id, locked_wallet.cached_balance - total)

        create_journal_for_canteen_sale(order)

        create_audit_log(cashier, "canteen.rfid.payment", order.id)
    COMMIT

    print_receipt(order)

    RETURN order
```

# 10. Alur Penerbitan Kartu RFID

## Saat siswa baru mendapat kartu

```text
Admin login
Admin pilih siswa
Admin tempel kartu kosong ke reader/writer
Sistem membaca UID/token
Sistem cek apakah kartu sudah pernah dipakai

Sistem mapping kartu ke siswa
Status kartu = active
Sistem membuat wallet jika belum ada
Sistem cetak/aktifkan kartu
```

Pseudo-code:

```text
FUNCTION issue_rfid_card(admin, device_id, student_id, raw_card_uid):
    authorize(admin, "rfid.issue")
    authorize_device(device_id, module = "rfid_management")

    uid_hash = hmac_sha256(SERVER_SECRET, raw_card_uid)

    IF card_uid_hash_exists(uid_hash):
        REJECT "Kartu sudah terdaftar"

    student = get_student(student_id)

    BEGIN_TRANSACTION
        deactivate_old_active_cards(student.id)

        card = create_rfid_card(
            student_id = student.id,
            card_uid_hash = uid_hash,
            card_public_id = generate_card_public_id(),
            card_type = detect_card_type(),
            status = "active",
            issued_at = now()
        )

        ensure_wallet_exists(student.id)

        create_rfid_card_event(card.id, "issued", device_id, admin.id)

        create_audit_log(admin, "rfid.issue", card.id)
    COMMIT

    RETURN card
```

```text
FUNCTION block_lost_card(admin, card_id, reason):
    authorize(admin, "rfid.block")

    card = get_card(card_id)

    BEGIN_TRANSACTION
        update card set status = "lost", blocked_at = now(), blocked_reason = reason

        create_rfid_card_event(
            card_id = card.id,
            event_type = "lost_reported",
            user_id = admin.id
        )

        create_audit_log(admin, "rfid.block_lost_card", card.id)
    COMMIT
```

# 15. Mekanisme Anti Kecurangan

## Rule wajib

```text
1. Top-up guru dibatasi per transaksi dan per hari.
2. Petugas kantin tidak bisa top-up.
3. Refund hanya admin/bendahara.
4. Void transaksi harus pakai alasan.
5. Void di atas nominal tertentu perlu approval.
6. Kartu yang sama tidak boleh transaksi terlalu cepat berulang.
7. Jika kartu dipakai di dua device hampir bersamaan, blokir sementara.
8. Jika transaksi terjadi di luar jam sekolah, tandai suspicious.
9. Jika top-up besar lalu langsung refund, tandai suspicious.
10. Jika saldo dikoreksi manual, wajib approval dua pihak.
```

## Tabel fraud flag

```text
security_flags
- id uuid pk
- unit_id uuid
- flag_type text
  contoh: repeated_void, unusual_topup, duplicate_card_scan, after_hour_transaction
- severity text
  low, medium, high, critical
- source_module text
- source_id uuid
- user_id uuid nullable
- device_id uuid nullable
- description text
- status text
  open, reviewed, dismissed, resolved
- created_at timestamp
```

Pseudo-code:

```text
FUNCTION check_risk_before_transaction(context):
    IF same_card_used_in_last_3_seconds(context.card_id):
        REJECT "Transaksi terlalu cepat"

    IF device_not_allowed(context.device_id, context.module):
        REJECT "Device tidak diizinkan"

    IF transaction_after_school_hours(context):
        create_security_flag("after_hour_transaction")

    IF amount_above_role_limit(context.user, context.amount):
        require_approval()

    IF card_used_from_two_locations_quickly(context.card_id):
        freeze_card_temporarily()
        create_security_flag("possible_card_clone")
```

# 16. Offline Mode: Sebaiknya Jangan untuk Pembayaran

Untuk kantin, kadang LAN/server bisa mati. Namun untuk keamanan, saya sarankan:

```text
Top-up: wajib online
Pembayaran kantin: wajib online
Issue kartu: wajib online
Refund/void: wajib online
```

Kenapa?

```text
- Kalau offline, saldo bisa minus
- Bisa terjadi transaksi dobel
- Sulit audit
- Risiko fraud lebih besar
```

Kalau tetap ingin ada offline mode, batasi ketat:

```text
- Hanya whitelist siswa tertentu
- Limit maksimal kecil, misal Rp10.000
- Hanya 1 device offline
- Harus sync segera
- Risiko selisih harus diterima
```

Tapi rekomendasi saya: **jangan offline dulu**. Lebih baik buat server lokal stabil dengan UPS.

# 24. Request Signing untuk PC Client

Supaya request dari PC client tidak mudah dipalsukan:

```text
signature = HMAC_SHA256(device_secret, method + path + body_hash + timestamp)
```

Backend cek:

```text
- device_id valid
- device aktif
- timestamp tidak terlalu lama
- signature cocok
- request_id belum pernah dipakai
```

Pseudo-code:

```text
FUNCTION verify_device_request(request):
    device = get_device(request.headers["X-Device-Id"])

    IF device.status != "active":
        REJECT

    timestamp = request.headers["X-Timestamp"]

    IF timestamp older than 2 minutes:
        REJECT

    expected_signature = hmac_sha256(
        device.secret,
        request.method + request.path + hash(request.body) + timestamp
    )

    IF expected_signature != request.headers["X-Signature"]:
        REJECT

    IF request_id_already_used(request.headers["X-Request-Id"]):
        REJECT

    mark_request_id_used()
```

# 25. Idempotency Wajib

Ini penting untuk mencegah transaksi dobel ketika jaringan lambat.

Contoh kasus:

```text
Kasir klik bayar
Jaringan lambat
Kasir klik lagi
Tanpa idempotency, saldo bisa kepotong dua kali
```

Solusi:

```text
Setiap transaksi punya X-Idempotency-Key
Jika request sama dikirim ulang, server mengembalikan hasil transaksi yang sama
Bukan membuat transaksi baru
```

Pseudo-code:

```text
FUNCTION process_with_idempotency(key, payload):
    existing = find_idempotency_record(key)

    IF existing exists:
        RETURN existing.response

    BEGIN_TRANSACTION
        save_idempotency_key(key, status = "processing")
        result = process_transaction(payload)
        save_idempotency_response(key, result)
    COMMIT

    RETURN result
```

# 30. Kesimpulan Review

Desain sebelumnya sudah kuat, tetapi untuk implementasi nyata saya akan menambahkan keputusan arsitektur berikut:

```text
1. Gunakan 1 PC server utama sebagai pusat backend, PostgreSQL, dan web app.
2. PC client hanya sebagai terminal kasir/admin/kantin.
3. RFID reader/writer terhubung ke PC client.
4. PC client tidak boleh langsung akses database.
5. Kartu RFID jangan menyimpan saldo.
6. Saldo wajib ada di server dan dicatat dengan ledger.
7. Untuk murah, UID-only bisa dipakai sebagai MVP dengan limit kecil.
8. Untuk aman jangka panjang, gunakan MIFARE DESFire EV3.
9. Semua transaksi harus online ke server utama.
10. Semua request harus dicek user, device, role, unit, limit, dan status kartu.
```

Arahan paling aman dan mudah:

```text
Backend:
Laravel/NestJS + PostgreSQL

Frontend:
Web admin + web kasir + web kantin

RFID:
Local bridge app kecil di PC client

Database:
Wallet ledger immutable

Security:
RBAC + device authorization + idempotency + audit log + approval
```

Dengan desain ini, sistem tetap **mudah diimplementasikan**, tetapi tidak mengorbankan keamanan transaksi siswa.
