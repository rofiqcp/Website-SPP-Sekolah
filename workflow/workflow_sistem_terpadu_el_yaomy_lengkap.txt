WORKFLOW SISTEM TERPADU EL YAOMY
PostgreSQL + Backend Python + Frontend HTML/React + Android WebView + RFID
Versi: Siap rancangan implementasi awal
Prioritas: Security, auditability, reliability, kemudahan penggunaan web dan HP

============================================================
0. RINGKASAN TUJUAN
============================================================

Sistem ini adalah platform terpadu untuk Yayasan Pendidikan El Yaomy Klaten yang menggabungkan:

1. Keuangan sekolah/yayasan.
2. Tagihan siswa dan pembayaran SPP.
3. Kasir sekolah.
4. Tabungan siswa/kelas/pegawai.
5. Dompet digital internal siswa.
6. E-kantin berbasis RFID/QR.
7. Inventaris dan aset.
8. Jurnal akuntansi otomatis.
9. Neraca dan laporan keuangan.
10. RAB dan approval pengeluaran.
11. Manajemen kartu RFID.
12. Web responsive untuk PC dan HP.
13. Android WebView untuk orang tua/siswa/guru/kepala sekolah.
14. Backend API Python yang aman.
15. PostgreSQL sebagai database utama.

Prinsip utama:

- Semua transaksi uang harus diproses di backend, bukan di frontend/client.
- Client tidak boleh akses langsung ke PostgreSQL.
- Saldo tidak disimpan di kartu RFID.
- Kartu RFID hanya identitas/token.
- Sumber kebenaran saldo adalah ledger PostgreSQL.
- Semua transaksi finansial harus immutable atau dikoreksi dengan reversal.
- Semua aksi penting wajib masuk audit log.
- Keamanan lebih penting daripada fitur cepat.
- UI harus minimalis, elegan, mudah dipakai di web desktop dan HP.

============================================================
1. STACK TEKNOLOGI
============================================================

1.1 Database

- PostgreSQL 16+.
- UUID primary key.
- BIGINT untuk nominal rupiah.
- JSONB untuk metadata/audit tambahan.
- Row Level Security optional tetapi sangat disarankan untuk multi-unit.
- Partitioning untuk tabel besar seperti audit_log, wallet_ledger, journal_entries, payment_webhooks.
- Backup harian otomatis.
- Point-in-time recovery jika tersedia.

1.2 Backend

- Python 3.10+.
- FastAPI sebagai REST API.
- SQLAlchemy 2.x atau SQLModel.
- Alembic untuk database migration.
- Pydantic untuk schema validation.
- Redis untuk cache, rate limit, queue ringan, session blacklist.
- Celery/RQ/Arq untuk background jobs.
- Gunicorn/Uvicorn worker.
- Object storage lokal/S3-compatible untuk bukti transaksi, nota, gambar aset, export PDF.

1.3 Frontend Web

- React + TypeScript.
- HTML5 responsive.
- Tailwind CSS atau CSS module minimalis.
- Vite sebagai bundler.
- React Query/TanStack Query untuk data fetching.
- Zustand/Redux Toolkit untuk state sederhana.
- PWA optional untuk installable web app.

1.4 Android

- Android native wrapper dengan WebView.
- Membuka domain web resmi sistem.
- Tidak memakai addJavascriptInterface kecuali benar-benar perlu.
- JavaScript diaktifkan hanya untuk domain resmi.
- SSL error wajib diblokir, bukan dilewati.

1.5 RFID

Mode yang didukung:

- Mode A: RFID keyboard/HID untuk kasir kantin dan scan cepat.
- Mode B: Web Serial untuk reader/writer serial di Chrome/Edge desktop.
- Mode C: Local bridge/native bridge hanya jika hardware tidak bisa langsung via web.

Rekomendasi MVP:

- Kantin menggunakan reader HID keyboard.
- Admin kartu menggunakan reader serial/Web Serial bila perlu tulis token.
- Saldo tetap di server PostgreSQL.

3. ROLE DAN HAK AKSES
============================================================

Role minimal:

1. Super Admin Yayasan
   - Kelola foundation, unit, user, role, permission, konfigurasi, backup, audit.

2. Admin Unit Sekolah
   - Kelola data siswa, kelas, pegawai, tagihan unit, kartu siswa unit.

3. Bendahara Yayasan
   - Konsolidasi laporan semua unit, jurnal, kas/bank, RAB, approval besar.

4. Bendahara Unit
   - Tagihan, pembayaran, kas unit, jurnal unit, laporan unit.

5. Kepala Sekolah
   - Dashboard, approval RAB/pengeluaran, laporan, tunggakan.

6. Wali Kelas
   - Lihat tagihan siswa kelasnya, laporan tunggakan kelas, top-up terbatas jika diberi izin.

7. Guru/Pegawai
   - Lihat transaksi pribadi, tabungan pegawai, fitur yang diberi akses.

8. Kasir Sekolah
   - Terima pembayaran tunai/non-tunai, top-up, cetak struk, closing shift.

9. Petugas Kantin
   - POS kantin, scan kartu, jual produk, closing shift kantin.

10. Petugas Gudang/Aset
    - Inventaris, aset, mutasi, opname.

11. Orang Tua/Wali
    - Lihat tagihan anak, bayar online, saldo, riwayat kantin, limit jajan, blokir kartu hilang.

12. Siswa
    - Lihat saldo, riwayat belanja, kartu/QR pribadi.

13. Auditor
    - Read-only laporan, jurnal, audit trail.

Prinsip akses:

- Role Based Access Control untuk permission umum.
- Object Level Authorization untuk data spesifik.
- Unit scoping: user hanya boleh akses unit yang diizinkan.
- Class scoping: wali kelas hanya kelasnya.
- Parent scoping: orang tua hanya anaknya sendiri.
- Device scoping: reader kantin tidak boleh top-up jika tidak diizinkan.

Pseudocode authorization:

FUNCTION authorize(user, permission, object = null):
    IF user.status != 'active':
        REJECT 'User tidak aktif'

    IF permission not in user.permissions:
        REJECT 'Tidak punya izin'

    IF object is not null:
        IF object.unit_id not in user.allowed_unit_ids:
            REJECT 'Tidak boleh akses unit ini'

        IF user.role == 'parent':
            IF object.student_id not in user.guardian_student_ids:
                REJECT 'Orang tua hanya boleh akses anak sendiri'

        IF user.role == 'homeroom_teacher':
            IF object.class_id not in user.allowed_class_ids:
                REJECT 'Wali kelas hanya boleh akses kelasnya'

    RETURN true

FUNCTION login(identifier, password, device_info):

FUNCTION generate_monthly_invoices(unit_id, period_month, period_year, actor):
    authorize(actor, 'billing.generate', unit_id)
    rules = get_active_billing_rules(unit_id, period_month, period_year)
    students = get_active_students(unit_id)

    FOR student IN students:

            IF rule.applies_to(student) == false:

                CONTINUE

            base_amount = rule.amount
            discount = calculate_student_discount(student, rule)

                    period_year = period_year,

                    journal = create_journal_for_invoice(invoice)
                    mark_invoice_posted(invoice, journal.id)

                audit_log(actor, 'billing.generate_invoice', invoice.id)
            COMMIT

            enqueue_notification(student.guardian, 'invoice_created', invoice.id)

FUNCTION create_online_payment(parent_user, invoice_ids, method):

            amount = total,
            method = method,
            reference = intent.id
        )

        save_gateway_reference(intent, gateway_response)
        audit_log(parent_user, 'payment.intent.create', intent.id)
    COMMIT

8.3 Webhook Payment Gateway

FUNCTION payment_webhook(provider, payload, signature):
    IF verify_gateway_signature(provider, payload, signature) == false:
        save_webhook_event(provider, payload, false, 'rejected')
        REJECT 'Invalid signature'

    external_id = payload.external_transaction_id

    IF webhook_already_processed(external_id):
        RETURN success_idempotent

    BEGIN_TRANSACTION
        save_webhook_event(provider, payload, true, 'processing')

        intent = find_payment_intent(payload.reference)
        IF intent is null:
            mark_webhook_failed('intent_not_found')
            REJECT 'Intent tidak ditemukan'

        IF payload.amount != intent.amount:
            mark_webhook_failed('amount_mismatch')
            REJECT 'Nominal tidak cocok'

        IF payload.status == 'PAID':
            payment = create_payment_from_intent(intent, external_id)
            allocate_payment_to_invoices(payment, intent.invoice_ids)
            journal = create_journal_for_payment(payment)
            intent.status = 'paid'
            payment.journal_id = journal.id
            audit_log(null, 'payment.webhook.paid', payment.id)

        mark_webhook_processed(external_id)
    COMMIT

    enqueue_receipt_notification(payment.id)
    RETURN success

FUNCTION topup_wallet(actor, wallet_id, amount, payment_method, source_device_id):
    authorize(actor, 'wallet.topup')
    wallet = get_wallet(wallet_id)
    authorize(actor, 'wallet.access', wallet)

    IF amount <= 0:
        REJECT 'Nominal tidak valid'

    IF actor.role == 'teacher':
        student = get_wallet_owner_student(wallet)
        IF student.class_id not in actor.allowed_class_ids:
            REJECT 'Guru hanya boleh top-up siswa kelasnya'
        IF amount > TEACHER_SINGLE_TOPUP_LIMIT:
            REJECT 'Nominal melebihi limit guru'

    IF amount >= REAUTH_TOPUP_THRESHOLD:
        require_reauthentication(actor)

    BEGIN_TRANSACTION
        locked_wallet = lock_wallet(wallet.id)
        balance_before = locked_wallet.cached_balance
        balance_after = balance_before + amount

        tx = create_wallet_transaction(
            wallet_id = wallet.id,
            amount = amount,
            transaction_type = 'topup',
            status = 'success',
            device_id = source_device_id,
            created_by = actor.id
        )

        insert_wallet_ledger(
            wallet_id = wallet.id,
            transaction_id = tx.id,
            direction = 'credit',
            transaction_type = 'topup',
            amount = amount,
            balance_before = balance_before,
            balance_after = balance_after,
            source_module = 'wallet',
            source_id = tx.id,
            created_by = actor.id
        )

        update_wallet_balance(wallet.id, balance_after)

        IF payment_method == 'cash':
            create_cash_movement_for_topup(actor, tx, amount)

        create_journal_for_wallet_topup(tx)
        audit_log(actor, 'wallet.topup', tx.id)
    COMMIT

    send_guardian_notification(wallet.owner_id, 'wallet_topup', tx.id)
    RETURN tx

9.3 Debit Wallet

FUNCTION debit_wallet(wallet_id, amount, source_module, source_id, actor):
    IF amount <= 0:
        REJECT 'Nominal tidak valid'

    BEGIN_TRANSACTION
        wallet = SELECT wallet FOR UPDATE

        IF wallet.status != 'active':
            REJECT 'Wallet tidak aktif'

        IF wallet.cached_balance < amount:
            REJECT 'Saldo tidak cukup'

        IF amount > wallet.single_transaction_limit:
            REJECT 'Melebihi limit transaksi'

        balance_before = wallet.cached_balance
        balance_after = balance_before - amount

        tx = create_wallet_transaction(...)
        insert_wallet_ledger(direction='debit', balance_before, balance_after)
        update_wallet_balance(wallet_id, balance_after)
        audit_log(actor, 'wallet.debit', tx.id)
    COMMIT

    RETURN tx

10. WORKFLOW RFID
============================================================

10.1 Prinsip RFID

- RFID UID/card token tidak boleh dianggap sebagai bukti kepemilikan mutlak.
- Untuk UID-only, wajib limit nominal rendah, audit, dan blokir cepat.
- Untuk keamanan lebih tinggi, gunakan MIFARE DESFire EV2/EV3.
- Saldo tidak disimpan di kartu.
- UID disimpan di database sebagai HMAC_SHA256(server_secret, raw_uid), bukan plaintext.

10.2 Mode RFID Keyboard/HID

Flow:

1. Kasir login ke POS.
2. Input scan RFID tersembunyi/fokus.
3. Reader mengirim UID seperti keyboard + Enter.
4. Frontend normalisasi UID.
5. Frontend kirim UID ke backend.
6. Backend validasi kartu, user, terminal, device, limit.
7. Backend mengembalikan data siswa/saldo.

Frontend pseudocode:

FUNCTION start_keyboard_rfid_listener():
    buffer = ''
    focus_hidden_input()

    ON keydown(event):
        IF event.key == 'Enter':
            raw_uid = buffer.trim()
            buffer = ''
            IF is_valid_rfid(raw_uid):
                handle_card_scanned(raw_uid)
        ELSE:
            buffer += event.key

FUNCTION handle_card_scanned(raw_uid):
    uid = normalize_uid(raw_uid)
    IF same_uid_scanned_within_2_seconds(uid):
        RETURN

    context = get_current_page_context()
    POST /api/rfid/scan { raw_uid: uid, mode: 'hid_keyboard', context }

FUNCTION open_serial_port(port):
    port.open(baudRate=9600, dataBits=8, stopBits=1, parity='none')
    WHILE port.readable:
        data = read_bytes()
        text = decode(data)
        append_to_buffer(text)
        IF complete_frame_detected(buffer):
            raw_uid = parse_uid(buffer)
            buffer = ''
            handle_card_scanned(raw_uid)

FUNCTION canteen_pay_by_rfid(cashier, device_id, raw_card_uid, cart_items):

    authorize(cashier, 'canteen.checkout')

    session = get_active_cashier_session(cashier.id, 'canteen')
    IF not session:
        REJECT 'Kasir belum buka shift'

    card = find_card_by_uid_hash(uid_hash)

    IF card is null:
        REJECT 'Kartu tidak terdaftar'

        REJECT 'Kartu tidak aktif'

    student = get_student(card.student_id)
    wallet = get_wallet(student.id)

    IF total <= 0:

    today_spent = get_today_canteen_spending(student.id)

    BEGIN_TRANSACTION

        order = create_canteen_order(student, cashier, session, total, 'wallet')

                IF product.stock_qty < item.qty:
                    REJECT 'Stok tidak cukup'
                decrease_stock(product.id, item.qty)

        wallet_tx = debit_wallet_inside_transaction(wallet.id, total, 'canteen', order.id, cashier)
        create_journal_for_canteen_sale(order, wallet_tx)
        create_audit_log(cashier, 'canteen.rfid.payment', order.id)
    COMMIT

    print_receipt(order)
    notify_guardian(student.id, 'canteen_purchase', order.id)

        audit_log(actor, 'journal.post', journal.id)

FUNCTION inventory_issue(actor, item_id, qty, destination, reason):
    authorize(actor, 'inventory.issue')
    IF qty <= 0:
        REJECT

    BEGIN_TRANSACTION
        item = lock_inventory_item(item_id)
        IF item.current_stock < qty:
            REJECT 'Stok tidak cukup'
        item.current_stock -= qty
        create_inventory_movement(item_id, 'out', qty, reason)
        audit_log(actor, 'inventory.issue', item_id)
    COMMIT

class MainActivity : AppCompatActivity() {
    private lateinit var webView: WebView
    private val appUrl = "https://sekolah.el-yaomy.sch.id"

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        webView = WebView(this)
        setContentView(webView)
        configureWebView()
        configureNavigation()
        webView.loadUrl(appUrl)
    }

    private fun configureWebView() {
        val settings = webView.settings
        settings.javaScriptEnabled = true
        settings.domStorageEnabled = true
        settings.allowFileAccess = false
        settings.allowContentAccess = false
        settings.mixedContentMode = WebSettings.MIXED_CONTENT_NEVER_ALLOW
        WebView.setWebContentsDebuggingEnabled(false)
        CookieManager.getInstance().setAcceptCookie(true)
        CookieManager.getInstance().setAcceptThirdPartyCookies(webView, false)
    }

    private fun configureNavigation() {
        webView.webViewClient = object : WebViewClient() {
            override fun shouldOverrideUrlLoading(view: WebView, request: WebResourceRequest): Boolean {
                val host = request.url.host ?: ""
                return if (host == "sekolah.el-yaomy.sch.id") {
                    false
                } else {
                    startActivity(Intent(Intent.ACTION_VIEW, request.url))
                    true
                }
            }

            override fun onReceivedSslError(view: WebView, handler: SslErrorHandler, error: SslError) {
                handler.cancel()
                showError("Koneksi tidak aman. Aplikasi diblokir.")
            }
        }

        webView.webChromeClient = object : WebChromeClient() {
            override fun onPermissionRequest(request: PermissionRequest) {
                request.deny()
            }
        }
    }
}

17.1 Prinsip Security

17.3 Proteksi API

- JWT access token pendek.
- Refresh token HttpOnly Secure SameSite.
- CSRF token untuk cookie-auth mutation.
- Rate limit login, scan RFID, payment create, webhook.
- Request body size limit.
- Input validation Pydantic.
- SQL injection dicegah dengan ORM/parameterized query.
- Password Argon2id/bcrypt.
- MFA untuk admin/bendahara.
- Re-authentication untuk refund, void, top-up besar, adjustment saldo.

17.4 Proteksi Payment

- Webhook wajib signature/HMAC.
- Webhook wajib idempotent.
- Nominal harus cocok.
- External transaction id unique.
- Status pembayaran tidak boleh dari frontend.
- Callback duplikat tidak boleh dobel posting.
- Refund/void wajib approval dan audit.

17.5 Proteksi RFID

- UID disimpan sebagai HMAC, bukan plaintext.
- Anti double scan.
- Rate limit scan per terminal.
- Kartu hilang bisa diblokir cepat.
- Device/terminal harus terdaftar.
- Device punya allowed_modules.
- Reader kantin tidak boleh issue card/top-up jika tidak diberi izin.
- UID-only hanya untuk nominal kecil.
- DESFire direkomendasikan untuk keamanan lebih tinggi.

17.6 Proteksi Database

- User database app punya privilege minimal.
- Tidak memakai superuser untuk aplikasi.
- Backup terenkripsi.
- Audit log append-only.
- Transaction isolation cukup minimal READ COMMITTED + SELECT FOR UPDATE untuk saldo.
- Constraint debit/credit non-negative.
- Unique constraint pada idempotency key, external transaction id, receipt number.

17.7 Proteksi File Upload

- Whitelist mime type.
- Scan extension dan magic bytes.
- Rename file acak.
- Simpan di object storage, bukan public web root langsung.
- File private memakai signed URL.
- Limit ukuran upload.

17.8 Proteksi dari Hacker Umum

Ancaman dan mitigasi:

1. SQL Injection
   - ORM/parameterized query.
   - Jangan string concat SQL.

2. XSS
   - React escaping default.
   - CSP ketat.
   - Sanitize rich text.

3. CSRF
   - SameSite cookie.
   - CSRF token untuk mutation.

4. IDOR/BOLA
   - Object-level authorization di setiap endpoint ID.

5. Brute force login
   - Rate limit.
   - Lock akun sementara.
   - MFA admin.

6. Session hijacking
   - HTTPS.
   - HttpOnly Secure cookie.
   - Short access token.

7. Replay transaksi
   - Idempotency key.
   - Nonce untuk terminal signature.

8. Manipulasi saldo
   - Ledger immutable.
   - Row lock.
   - Reversal.
   - Audit log.

9. Webhook palsu
   - HMAC signature.
   - IP allowlist jika tersedia.
   - Nominal matching.

10. Client kasir disusupi
    - Device scoping.
    - Limit nominal.
    - Audit.
    - Tidak ada akses database.

18. TERMINAL ENROLLMENT AMAN
============================================================

18.1 Tujuan

Mendaftarkan PC kasir/admin agar server tahu terminal mana yang boleh menjalankan modul tertentu.

18.2 Flow

1. Super admin login di PC client.
2. Buka menu Terminal.
3. Klik Daftarkan PC Ini.
4. Pilih lokasi dan modul.
5. Browser membuat keypair Web Crypto non-extractable.
6. Public key dikirim ke server.
7. Private key disimpan di IndexedDB.
8. Setiap request sensitif ditandatangani.

Pseudocode frontend:

FUNCTION enroll_terminal(admin, terminal_name, location, allowed_modules):
    keypair = crypto.subtle.generateKey(ECDSA_P256, extractable=false, usages=['sign','verify'])
    public_key = export_public_key(keypair.publicKey)
    save_private_key_to_indexeddb(keypair.privateKey)
    response = POST /api/terminals/enroll { terminal_name, location, allowed_modules, public_key }
    save_terminal_id_to_indexeddb(response.terminal_id)

FUNCTION send_secure_terminal_request(payload):
    terminal_id = get_terminal_id()
    private_key = get_private_key()
    nonce = GET /api/terminals/nonce
    signature = sign(private_key, hash(payload + nonce))
    POST API with headers:
        X-Terminal-Id
        X-Terminal-Nonce
        X-Terminal-Signature

Pseudocode backend:

FUNCTION verify_terminal_request(request):
    terminal = get_terminal(request.header.X-Terminal-Id)
    IF terminal.status != 'active':
        REJECT
    IF request.module not in terminal.allowed_modules:
        REJECT
    IF nonce_already_used(request.nonce):
        REJECT
    verify_signature(terminal.public_key, request.body + request.nonce, request.signature)
    mark_nonce_used(request.nonce)

26. KESIMPULAN DESAIN
============================================================

Sistem ini harus dibangun sebagai platform keuangan sekolah yang aman, modular, dan audit-friendly. Bagian paling penting bukan tampilan atau fitur banyak, tetapi fondasi keamanan:

1. Backend API menjadi satu-satunya pintu transaksi.
2. PostgreSQL menyimpan ledger yang benar.
3. RFID hanya identitas, bukan penyimpan saldo.
4. Semua transaksi finansial menggunakan database transaction dan row lock.
5. Semua perubahan penting memiliki audit trail.
6. Role dan object-level authorization wajib diterapkan.
7. UI dibuat sederhana agar semua role bisa menggunakan tanpa kebingungan.
8. Implementasi dilakukan bertahap agar cepat dipakai tetapi tetap aman.

Dokumen ini bisa menjadi blueprint awal untuk tim developer membuat database migration, backend service, frontend React, Android WebView, dan integrasi RFID secara bertahap.
